SA and CRC at the transmitter: mode 10 case by case

Cheat sheet for eth_run_test_ops = 10 (eth_mac_sa_cpc_lb, file eth_sa_functions.c). STM32H755, RM0399 Rev 4. Written before running on the board: section 8 gets filled in once there is a log.

Mnemonic: The transmitter can rewrite the source address by itself (SAIC per frame, SARC for every frame; MACA0 or MACA1) and decide on pad and FCS by itself (CPC). 1. What mode 10 tests

The earlier modes tested the transmitter inserting tags (4, 5), splitting TCP (6) and computing IP checksums (7). Mode 10 tests the two remaining things the transmitter can do to a frame: rewrite the 6 source address bytes and decide on pad + FCS. Both are commanded in TDES3 of the first descriptor (p.3051-3052), and SA also has a global switch, ETH_MACCR.SARC. The frame loops through loopback back to the receiver; the receiver and the MTL RX queue show the result.

3. Pad and FCS: CPC at the transmitter, FUP / FEP at the receiver

Normally (CPC = 00) the transmitter pads short frames up to 60 bytes and appends the 4-byte FCS, so the wire always sees ≥ 64 bytes and a correct CRC. The other three codes switch off parts of that, which produces two kinds of bad frame: runts (shorter than 64 bytes) and bad CRC.

TDES3.CPC [27:26] (p.3051)Name in the codeWhat the transmitter doesUsed whenCase
00TDES3_CPC_CRC_PADpad to 60 + FCSdefault, every other modeA..G
01TDES3_CPC_CRC_NOPADFCS, no padsoftware pads itself; used here to create a runtH1a, H1b
10TDES3_CPC_NONEnothing at allthe buffer already has both pad and FCS (forwarding a whole frame)H2a, H2b
11TDES3_CPC_CRC_REPLACErecompute the FCS over the last 4 bytesthe buffer has room for the FCS but the old value cannot be trustedH3
ETH_MTLRXQOMR (p.3106)Name in the code= 0 (default)= 1
FUP [3] Forward Undersized good PacketsMTLRXQOMR_FUPdrop every frame < 64 bytesforward error-free runts to the DMA, "including pad and CRC"
FEP [4] Forward Error PacketsMTLRXQOMR_FEPdrop bad frames (CRC, RE, watchdog, overflow), unless transfer has already started in threshold modeforward to the DMA with RDES3.ES = 1 and an error flag (CE for CRC), except bad runts
RSF = 0 in mac_init_100m (threshold mode, RTC = 64 bytes): the MTL starts forwarding a frame as soon as 64 bytes are in the queue, before it knows whether the frame has an error. The 64-byte frame of H2a sits exactly on that boundary, so "FEP = 0 drops bad frames" may not happen. That is why the code does not grade the descriptor in H2a, only MMC +1. To be sure, enable RSF = 1 (store-and-forward) and run H2a again.
