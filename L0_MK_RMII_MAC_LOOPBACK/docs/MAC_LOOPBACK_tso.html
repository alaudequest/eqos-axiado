TSO: the MAC splits TCP frames by itself

Mode 6 (eth_run_test_ops = 6, eth_mac_tso_lb in eth_tso_functions.c). TCP Segmentation Offload on the STM32H755, RM0399 Rev 4 §61.5.6 p.2991-2997, programming guide §61.9.13 p.3045.

Mnemonic: One descriptor, two buffers, bit TSE. MSS in the context descriptor or in DMACCR, whichever is written last wins. The MAC patches 6 header fields in each segment.

headercontext descriptorregisterdone by MAC / DMAfield patched by MAC

1. The problem and how TSO solves it

Ethernet carries at most 1500 bytes of payload per frame. An application that wants to send 3000 bytes of TCP must turn it into 3 frames, each with its own header carrying the right sequence number, the right length and the right checksum. Without TSO the CPU does all of that. With TSO the CPU writes one big frame, marks TSE = 1, and the DMA and MAC split it by themselves.

The header is written only once but the DMA reads it again for every segment (buffer 1 is read n times, buffer 2 is read once, MSS bytes at a time). That is why the header must sit alone in buffer 1, without a single payload byte mixed in (p.2996).

Group 2: MSS, the maximum number of payload bytes per segment. Two sources, whichever is written last wins

A context descriptor has no buffer: TDES0 = TDES1 = 0, TDES2 holds the MSS, TDES3 has CTXT and TCMSSV ("MSS valid"). OSTC [27] must be 0, otherwise TDES2 is taken as a timestamp. It sits right before the frame descriptor in the ring and needs no tail write of its own. The DMA reads it, stores the MSS, closes it with OWN = 0 and CDE [23] = 0, then goes on to read the frame.

Group 3: the frame's descriptor, fields that change meaning when TSE = 1

Why CIC is gone: CIC is the choice of "which checksum the MAC computes". With TSO the MAC must compute both the IP and the TCP checksum for every segment, because each segment has a different header that the CPU has never seen. So that bit no longer means anything, and its room is reused for the 18-bit TPL (payload up to 262143 bytes).
Why both HL and THL are needed: HL tells the DMA how many header bytes to copy onto each segment (54). THL tells the MAC how long the TCP header is, so it can find the checksum field and the payload, because a TCP header can carry options (20..60 bytes).
