VLAN tag: who inserts it, what value, from where

Cheat sheet for mode 4 (one tag) and mode 5 (QinQ, two tags) of the MAC loopback test. STM32H755, RM0399 Rev 4.

Mnemonic: Value in the context. Outer command in the frame. Inner command in the context. VLP = 1 and the register takes over.

context descriptornormal descriptor (frame)MAC registerdone by MAC

1. The frame before and after the MAC inserts the tag

The CPU only writes a bare frame. For each tag the MAC inserts 4 extra bytes right after the SA, pushing the EtherType and the payload back by 4 bytes.

One tag = 4 bytes = type + value

2. Main diagram: where the value comes from, where the command comes from

Each tag has two things the MAC needs to know: the value (2-byte TCI) and the command (none / remove / insert / replace). Each has two sources, chosen by a "switch" bit in a register. The red path is the switch position used in this project.

Memory aid 1: read the bit names as questions. VLTI = "VLan Tag from descrIptor?" (value from the descriptor or from the register). VLP = "VLan Priority to register?" (does the register or the descriptor decide the command). VLC = "VLan Control" = the command in the register. CSVL = "Customer or Service VLan" = type 0x8100 or 0x88A8.
Memory aid 2: the four commands of VTIR and IVTIR are encoded the same way: 00 none · 01 remove · 10 insert · 11 replace. Remember "the bigger the number, the more it interferes": 0 does nothing, 1 removes, 2 adds, 3 replaces.

3. Two descriptors travelling together in the TX ring

A context descriptor has no buffer. It only loads parameters into the MAC, then the DMA closes it (OWN = 0). The frame right after it uses those parameters.

Receive-side VLAN filter (mode 8, 9): lessons from the board on 2026-11-12 and 11-13

Each case of mode 8 is explained separately on the VLAN RX (mode 8, 9) page. Below is a summary.

The filter is a whitelist for exactly one tag type (ERSVLM chooses C or S), not a gate that blocks everything else. The gatekeeper asks two questions: (1) is the tag the right type? (2) does the number match VL / the hash table? If question 1 fails, question 2 is not asked and nothing is blocked either.

untagged frame                            -> out of scope  -> received
tagged, right type, number matches        -> match         -> received, VF = 1
tagged, right type, number differs        -> no match      -> VTFE = 1: DROPPED, no descriptor
tagged, WRONG type (ERSVLM)               -> out of scope  -> received intact, RS2V = 0, VF = - (K1; mode 9 E/F board 11-16)
ERIVLT = 1 but the frame has only one tag -> out of scope  -> received intact, RS2V = 0, VF = - (board 11-13)
tagged, compared but MISSED, VTFE = 0     -> received (stripped/kept per EVLS), RS2V = 0, VF = - : the MAC never reports VF = 0 (mode 9 C/D1 board 11-16)
DOVLTC = 1                                -> skip question 1, always compare the number (case K2)
VL = 0                                    -> every tag matches, even with VTHM = 1      (case G)
VTIM = 1                                  -> invert the result of question 2: blacklist (case F)
VTHM = 1                                  -> adds matching through a 16-entry hash table, in parallel with VL

The MMC counter ETH_RX_UNICAST_PACKETS_GOOD also counts frames dropped by the VLAN filter: it sits before the filter, so it cannot be used as evidence of a drop.
