Table-driven MAC address filter: mode 1 case by case

Cheat sheet for eth_run_test_ops = 1 (eth_mac_filter_lb, file eth_filter_functions.c). STM32H755, RM0399 Rev 4. This is the address-filter test written before mode 11, in the CASES[] table style: 24 rows, each row a rule + a frame + a prediction. Run on the board on 2026-10-16 and 2026-10-20: 24/24. Mode 11 (its own page) redoes the same topic in framework style and adds slots 2 and 3.

Mnemonic: One case = write the hash table, write MACA1, write MACPFR (in exactly that order), send a 22-byte frame carrying "FILT" + a sequence number, then ask: did it come back? RDES2 is only written by the MAC on a slot 1 match, a hash match, or RA = 1.

1. What mode 1 tests

In mode 0 and 2..10, mac_basic_init leaves ETH_MACPFR.PR = 1, so the MAC accepts every DA. Mode 1 turns PR off (except case A1) and tests each switch of the address filter: the perfect slots MACA0 / MACA1, the MBC byte mask, broadcast and DBF, multicast with PM and the hash table, unicast through the hash with HUC / HPF, the DAIF inversion, Receive All, and sender filtering with SAF. Each case is one row of the CASES[] table; adding a case = adding a row.

It differs from mode 11 in three ways: (1) the frame is 22 bytes and the MAC pads it to 60, so only the first 22 bytes are compared; (2) only slot 1 is used, no slot 2 or 3; (3) the results print as one compact table, with frame dumps at the end. Mode 11 has step-by-step af_case, FLOW, and a separate RS2V column.

hashDA = bit_reverse32(crc32_ieee(addr, 6)) >> 26: the Ethernet CRC-32 of the 6 bytes (bit 0 of byte 0 first), bit-reversed over 32 bits, top 6 bits taken. The board confirms it at D3 D4 D6 D7 E1: RDES2.MADRM = exactly this number. The two LEAK addresses were found by trying last bytes until the bits collided: an illustration of the hash's "imperfect filtering".

5. The 22-byte frame and how it is recognised

TX 22 bytes: DA (6) | SA (6) | 88 B5 | 46 49 4C 54 ("FILT") | n (case number) | 00 00 00
RX 60 bytes: the 22 bytes above + 38 zero bytes padded by the MAC (ETH_MACCR.ACS = 1 keeps the pad, CST = 1 drops the FCS)

Why "FILT" + n is needed: a frame held back by the filter never comes back, but a frame from the previous case may still be in the queue. run_case calls eth_rx_flush first, then while receiving it loops at most MAC_100M_RX_DESC_CNT times and only accepts a frame with the right case number; len = −1 (5 ms elapsed) is DROP. Each case keeps RDES2, RDES3, the 22 sent bytes and the first 64 received bytes for the dump at the end.
